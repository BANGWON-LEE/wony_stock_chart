# 의사결정기록 001: MVP 프론트엔드는 React + Vite + Tailwind CSS로 구성한다

## 상태
확정 (Accepted)

## 일자
2026-05-12

## 배경
- MVP 목표는 빠른 구현/검증이며, 핵심 기능은 로그인, 포트폴리오 조회, 실시간 시세 차트(WebSocket), 알림 규칙 관리다.
- 초기 릴리즈는 SEO보다 인증 후 대시보드 UX와 실시간 상호작용이 더 중요하다.
- 팀은 React 개발 경험이 있고, 서버 사이드 렌더링/라우팅 프레임워크에 대한 추가 러닝코스트를 최소화해야 한다.

## 결정
MVP 프론트엔드는 `React + Vite`를 사용하고, CSS 스타일링에는 `Tailwind CSS`를 사용한다.

## 선택 이유
1. MVP 구현 속도에 유리하다.
- Vite 기반 개발 서버/빌드 속도가 빠르고, 초기 구조를 단순하게 가져갈 수 있다.

2. 현재 제품 요구와 잘 맞는다.
- 주요 화면은 로그인 이후 대시보드 중심이며, 실시간 시세/상태 업데이트가 핵심이다.
- SSR/SSG 중심 이점보다 클라이언트 상호작용 최적화가 우선순위다.

3. 운영 복잡도를 줄인다.
- Next.js의 서버 컴포넌트/라우팅/배포 모델을 초기에 도입하지 않아도 MVP 범위를 충분히 커버할 수 있다.

4. 일관된 UI 구현과 빠른 반복에 유리하다.
- Tailwind CSS의 유틸리티 클래스와 디자인 토큰 설정을 사용해 임의의 색상·간격 사용을 줄인다.
- 컴포넌트와 스타일의 변경 범위를 함께 관리해 MVP 화면 구현 속도를 높인다.

## 영향
### 장점
- 초기 개발 및 디버깅 속도가 빠르다.
- 실시간 WebSocket UI, 차트 상호작용 구현이 단순하다.
- 배포 파이프라인(정적 자산 + API 서버 분리)이 명확하다.
- 색상, 간격, 타이포그래피 등의 디자인 토큰을 Tailwind CSS 테마와 연결할 수 있다.

### 단점
- 향후 SEO/콘텐츠 페이지 요구가 커지면 SSR 재검토가 필요하다.
- 라우팅, 데이터패칭, 성능 최적화 가이드를 팀에서 명시적으로 관리해야 한다.
- 복잡한 반복 스타일은 컴포넌트로 추출하지 않으면 클래스 문자열이 길어질 수 있다.

## 실행 메모
1. 기본 스택: `React 19 + TypeScript + Vite + Tailwind CSS`.
2. 라우팅: `react-router-dom`.
3. 서버 상태/캐시: `@tanstack/react-query`.
4. 실시간 시세: WebSocket 클라이언트 모듈을 별도 레이어(`src/realtime`)로 분리한다.
5. 환경변수: `.env`에 API/WS 엔드포인트를 분리(`VITE_API_BASE_URL`, `VITE_WS_URL`).
6. 디자인 토큰: Primitive 값과 Semantic 역할을 분리하고 Tailwind CSS 테마 변수에 연결한다.

## 재검토 조건
- 퍼블릭 랜딩/SEO 요구가 MVP 이후 핵심 목표로 상향되는 경우
- SSR이 성능/보안/개발 생산성 측면에서 명확한 이점을 제공하는 경우
- 팀 운영에서 Next.js 전환 비용보다 유지비 절감 효과가 더 큰 경우
