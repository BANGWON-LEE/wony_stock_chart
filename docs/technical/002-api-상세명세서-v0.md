# API 상세명세서 v0

## 1. 문서 목적
- MVP 백엔드 API/웹소켓 계약을 고정한다.
- 프론트엔드/백엔드 병렬 개발이 가능하도록 요청/응답/에러 규칙을 정의한다.

## 2. 공통 규칙
### Base URL
- `https://api.<service-domain>`

### 인증
- 로그인 성공 시 JWT Access Token 발급
- Access Token 만료시간: `3600초(1시간)`
- Refresh Token 회전 정책 사용 (`POST /auth/refresh`)
- 보호 API는 `Authorization: Bearer <token>` 필수

### 공통 헤더
- `Content-Type: application/json`
- `X-Request-Id` (선택, 추적용)

### 시간/통화 규칙
- 시간은 ISO 8601 UTC 사용 (`2026-05-08T10:30:00Z`)
- 금액은 Decimal 문자열로 전달 (부동소수 오차 방지)

### 공통 응답 포맷
```json
{
  "success": true,
  "data": {}
}
```

### 공통 에러 포맷
```json
{
  "success": false,
  "error": {
    "code": "INVALID_INPUT",
    "message": "요청 필드가 올바르지 않습니다.",
    "details": {}
  }
}
```

## 3. 인증 API
## `POST /auth/signup`
### Request
```json
{
  "email": "user@example.com",
  "password": "StrongPass!123"
}
```

### Response 201
```json
{
  "success": true,
  "data": {
    "user": {
      "id": "u_123",
      "email": "user@example.com",
      "createdAt": "2026-05-08T10:30:00Z"
    }
  }
}
```

## `POST /auth/login`
### Request
```json
{
  "email": "user@example.com",
  "password": "StrongPass!123"
}
```

## `POST /auth/refresh`
### Request
```json
{
  "refreshToken": "<refresh_token>"
}
```

### Response 200
```json
{
  "success": true,
  "data": {
    "accessToken": "<jwt>",
    "expiresIn": 3600,
    "refreshToken": "<rotated_refresh_token>"
  }
}
```

## `POST /auth/logout`
### Request
```json
{
  "refreshToken": "<refresh_token>"
}
```

### Response 204
- 본문 없음

### Response 200
```json
{
  "success": true,
  "data": {
    "accessToken": "<jwt>",
    "expiresIn": 3600,
    "user": {
      "id": "u_123",
      "email": "user@example.com"
    }
  }
}
```

## 7. 시장/차트 API
## `GET /markets/:market/symbols/:symbol/candles`
설명: 종목별 과거 차트 캔들 데이터를 조회한다. MVP는 일봉(`1d`)만 지원하며, 서버는 DB 캐시를 우선 조회하고 부족한 기간은 브로커 API에서 보충 후 캐싱한다.

### Path
- `market`: `KR` | `US`
- `symbol`: 종목 코드 또는 티커

### Query
- `interval` (required): `1d`
- `from` (optional): `YYYY-MM-DD`
- `to` (optional): `YYYY-MM-DD`
- `limit` (optional): default `300`, max `1000`

### Response 200
```json
{
  "success": true,
  "data": {
    "market": "KR",
    "symbol": "005930",
    "interval": "1d",
    "source": "CACHE",
    "stale": false,
    "candles": [
      {
        "time": "2026-06-19T00:00:00Z",
        "open": "74500",
        "high": "75200",
        "low": "74100",
        "close": "75000",
        "volume": "12345678"
      }
    ]
  }
}
```

### Error
- `400 INVALID_INPUT`: 지원하지 않는 interval, 잘못된 날짜 범위, limit 초과
- `404 SYMBOL_NOT_FOUND`: 브로커/캐시에서 종목을 찾을 수 없음
- `503 BROKER_UNAVAILABLE`: 캐시가 없고 브로커 조회도 실패

### Cache/Fallback
- `source`: `CACHE` | `BROKER_REFRESHED`
- `stale`: 브로커 보충 조회 실패 후 기존 DB 데이터로 응답한 경우 `true`

## 9. 에러 코드 정의
- `INVALID_INPUT` (400): 필수 필드 누락/형식 오류
- `UNAUTHORIZED` (401): 인증 실패/토큰 만료
- `FORBIDDEN` (403): 리소스 접근 권한 없음
- `NOT_FOUND` (404): 리소스 미존재
- `SYMBOL_NOT_FOUND` (404): 차트 조회 대상 종목 미존재
- `CONFLICT` (409): 중복 규칙 등 상태 충돌
- `RATE_LIMITED` (429): 요청 제한 초과
- `INTERNAL_ERROR` (500): 서버 내부 오류
- `BROKER_API_ERROR` (502): 브로커 연동 오류
- `BROKER_UNAVAILABLE` (503): 캐시가 없고 브로커 조회도 실패

## 10. 유효성 규칙
- `email`: RFC 형식 검증
- `password`: 최소 10자, 영문/숫자/특수문자 포함
- `targetValue`: 0 초과 Decimal 문자열
- `channels`: MVP는 `IN_APP`만 허용
- `scope = portfolio` 인 경우 `symbol`은 null 이어야 함
- `scope = symbol` 인 경우 `symbol` 필수
- `candles.interval`: MVP는 `1d`만 허용
- `candles.limit`: 기본 `300`, 최대 `1000`

## 11. 성능/운영 고려사항
- `GET /portfolio/*` 응답은 최신 캐시 우선 사용 가능
- `GET /markets/:market/symbols/:symbol/candles`는 DB 캐시 우선 사용
- `alerts/history`는 cursor pagination 사용
- `alerts/history` 정렬은 최신순 고정(`triggeredAt DESC`)
- WebSocket 구독 심볼 수 제한(초기 1세션당 50개)
- API/WS 모두 `X-Request-Id`로 추적 가능해야 함

## 12. 오픈 이슈
1. JWT 만료시간(`expiresIn`): 확정 (`3600`)
2. Refresh Token 정책: 확정 (회전 + 로그아웃 폐기)
3. `portfolio_tick` 이벤트: MVP 포함 확정
4. 알림 채널: MVP `IN_APP` only 확정
5. 알림 이력 조회 정렬 기준: 최신순 고정 확정
6. 차트 MVP interval: `1d` only 확정
